# Notebook 01–02 independent encoding audit

No original code was modified. Reproductions: `check.py` and `penalty_scan.py` alongside this report; outputs in JSON. Scripts use repository virtualenv, no cloud jobs.

## Findings

1. **No polynomial encoding bug on tested instances.** Independently evaluate the original polynomial on every 14-bit slack state (16,384), every 4-bit reduced state (16), and every 20-bit reduced state (1,048,576). Maximum expansion errors: 1.82e-11, 1.42e-13, 1.38e-10, respectively (roundoff). All exact global minima decode to the constrained optimum: respectively 2, 2, 6 labelled states. AST-extracted notebook 01 builders from main and qubo-solver worktree agree exactly with shared helper. Sources: notebook01 build_qubo lines 192–222; notebook02 lines 198–216; track_a.py lines 147–166, 221–248. This does not prove all arbitrary instances or simulation code.

2. **Textbook baseline penalty choice compresses the objective severely and is not tuned.** The certificate rule picks both penalties 168. Exhaustive cheap scan of 7,500 independent penalty pairs finds 459 with correct optimum. Best scanned estimated device margin uses assignment weight 96.5462267743 and capacity weight 1.36142771283. Same raw optimal-versus-wrong-clustering margin 1.0551459418, but device-allowed scale increases from 0.0102140056 to 0.2869416814, giving 0.0107772666 versus 0.3027653506 rad/us, a 28.09-fold improvement. Maximum pair coupling falls from 5424.5391 to 193.09245. This estimate uses maximum interaction and detuning limits; it is not a measured embedding scale or a quantum success prediction. The existing notebook scan only covers weights from 8.4 to 252, so excludes the promising capacity weight entirely (notebook01 lines 294–304). This is a diagnostic using known exact optimum, not an independently selected production parameter. Strong evidence that the original poor result cannot establish an atom-count scaling limit.

3. **Proxy impossibility is real, not merely a coarse grid.** For first 26 capacity-active small instances, exact inequalities establish 25 admit a strictly correct proxy optimum and one does not. For seed 114, beating an over-capacity split requires mu greater than 0.5363763110, while beating a more balanced but worse split requires mu less than 0.4200114522. No mu satisfies both. Original constrained optimum is cost 65.74631218, loads 2/7; alternatives are cost 59.30979645 loads 1/8 and cost 70.78644961 loads 4/5. Thus increasing scan range/resolution cannot fix it. Non-oracle equal-weight rule produces correct optimum on 15/26 only. Sources notebook02 lines 9–11 and 286–315; track_a.choose_mu lines 175–187. Notebook02 nanargmax at line 313 crashes on this no-solution case; shared choose_mu returns None.

4. **Notebook02 includes unsupported and stale interpretation.** Lines 702–703 state exact-coupling 45.5% is a ceiling caused by problem spacing rather than schedule. A gap and one schedule do not establish an upper bound on success; timing/schedule optimization can change it. Lines 628–644 and 711–712 reproduce stale slack results and claim notebook01 has unfixed ramp/scaling bugs, despite fixes and updated cloud results. Handoff claim slack fails everywhere is also contradicted by supplied cloud log: physical DMM feasibility 45.8%, optimal 0%; ideal coupling feasibility 8.3%, optimal 2.4%. Do not merge feasibility and optimality failure.

5. **Known-answer calibration and restricted test population must remain explicit.** Notebook02 calibrates mu by identifying reference-optimal clusterings before choosing the parameter (lines 300–313). Correct proxy ground state is therefore a calibration criterion, not a blind success statistic. Instance selection filters to feasible capacity-active problems; results concern that population, not uniformly generated routing problems. Exact random slack baseline is 3.125% feasible, 0.78125% optimal; reduced small-instance baseline is 50% and 12.5% for seed12. Shot seeds quantify sampling noise, not independent problem or embedding robustness.

## Decisive next experiment

Compare baseline slack versus the smaller independently weighted penalties using identical cloud emulator exact-coupling+DMM diagnostics at matched physical scale policy, duration, pulse shape and shot count. First validate pulse coefficients and exact final energies. Then refit actual layouts for the same parameter choices and compare final-energy optimum ranks before spending simulation jobs. If exact-coupling tuned success improves but physical success stays poor, geometry is implicated; if neither improves, test sweep schedule/duration. Do not claim a size ceiling from these one-instance experiments. No cloud cost incurred by this audit.

## Independent held-out model screening

A separate, frozen-source reproduction (`heldout.py`, importing `frozen_track_a.py`) scanned seeds 400 through 1202 inclusive. Of these 803 candidates, the first 100 feasible capacity-active instances were retained, selected seeds 406 through 1202. All are disjoint from the original 26 selected seeds. Full per-instance output, original seed list, and frozen-source SHA-256 are in `heldout.json`.

- Exact continuous balance-weight inequalities admit the original optimal clustering on 96/100 instances; 4/100 are impossible for any nonnegative balance weight. This calculation does not use the 81-point calibration grid.
- The equal-weight rule yields original-optimal ground states on 57/100, feasible ground states on 61/100. Thus 39/100 are infeasible and 4/100 are feasible but suboptimal even before hardware mapping or pulse simulation.
- Counting any versus all tied ground states produces identical counts. Tight original-objective tolerance (absolute 1e-8, no relative tolerance) agrees with existing optimum classification on all 100 instances.
- Impossible instance bounds (required lower exceeds allowed upper): seed 583: 1.31179 versus 0.90617; seed 765: 1.83983 versus 0.30655; seed 768: 14.54827 versus 0.48274; seed 787: 4.10385 versus 1.57690. These are not grid-resolution failures or equality/tie edge cases.

Interpretation: the previously observed 15/26 equal-weight optimality (57.7%) repeats at 57/100 on fresh instances. This supports a modeling limitation independent of pulse choice. The population remains deliberately capacity-active; it is not a random unfiltered routing benchmark. No emulation or cloud resources were used, and no production modules were edited.
